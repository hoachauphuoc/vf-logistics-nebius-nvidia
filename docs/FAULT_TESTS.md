# Real Cloud Run faults on a separate service

Two failures cannot be shown on the production service without harming it: a process killed right
after Pub/Sub accepted a decision, and a gateway 504 on Execute while the work finished. Both are run
on **`vf-app-faulttest`**, a separate Cloud Run service built from the same source as `vf-app`.

| What differs from `vf-app` | Why |
|---|---|
| `FLASK_APP_MODULE=vf_logistics.faulttest:app` | `entrypoint.sh` starts gunicorn on it; `vf-app` never sets it and runs `vf_logistics.app:app` as before |
| `FAULT=kill_after_publish` or `slow_after_execute` | the one fault installed (`src/vf_logistics/faulttest.py`) |
| `FAULT_TEST_ALLOWED=true` | the module refuses to load without it, on `K_SERVICE=vf-app`, and for any other `FAULT` |
| topic `faulttest-decisions`, ledger `faulttest-sent-ledger` | no test decision reaches `case-decisions` or the receivers on it |
| `MULTI_TENANT=true`, tenant `faulttest` | the production board is single-tenant and never reads these cases |
| its own `VF_API_KEY` and `VF_SESSION_SECRET` | generated by `scripts/faulttest_setup.py` into `orchestrator/runs/faulttest` (git-ignored), never printed |

`scripts/faulttest_run.py` seeds a case that needs an exception in the `faulttest` tenant, releases it
as `op@faulttest.test`, and reads the result from the case and from the count subscription.

## Run it (PowerShell, one command each, with Application Default Credentials)

1. A topic and its subscriptions, the ledger first so it holds every message:

```powershell
gcloud pubsub topics create faulttest-decisions
```

```powershell
gcloud pubsub subscriptions create faulttest-sent-ledger --topic=faulttest-decisions --message-retention-duration=1d
```

```powershell
gcloud pubsub subscriptions create faulttest-count --topic=faulttest-decisions
```

```powershell
gcloud pubsub subscriptions add-iam-policy-binding faulttest-sent-ledger --member="serviceAccount:350828852747-compute@developer.gserviceaccount.com" --role=roles/pubsub.subscriber
```

2. Settings and deploy, killing mode:

```powershell
python scripts/faulttest_setup.py --project vf-fraud-detection-phuochoa
```

```powershell
gcloud run deploy vf-app-faulttest --source . --region asia-southeast1 --allow-unauthenticated --env-vars-file orchestrator/runs/faulttest/env.yaml
```

3. The kill (about 7 minutes: the claim lease is 300 s):

```powershell
python scripts/faulttest_run.py kill --base <faulttest-url> --project vf-fraud-detection-phuochoa
```

Passes when the worker died after the broker accepted (case `EXECUTING`, no publish record), the Resume
after the lease ended `RELEASED_BY_HUMAN`, and the decision is on the topic once.

4. The gateway 504: switch the fault and give the service a 10-second timeout:

```powershell
python scripts/faulttest_setup.py --project vf-fraud-detection-phuochoa --fault slow_after_execute
```

```powershell
gcloud run services update vf-app-faulttest --region asia-southeast1 --timeout 10 --env-vars-file orchestrator/runs/faulttest/env.yaml
```

```powershell
python scripts/faulttest_run.py gateway504 --base <faulttest-url> --project vf-fraud-detection-phuochoa
```

Passes when Cloud Run answered 504, the case is `RELEASED_BY_HUMAN` behind it, a retry is refused with
409, and the decision is on the topic once.

5. Clean up everything the run created:

```powershell
python scripts/faulttest_run.py cleanup --project vf-fraud-detection-phuochoa --yes
```

```powershell
gcloud run services delete vf-app-faulttest --region asia-southeast1 --quiet
```

```powershell
gcloud pubsub subscriptions delete faulttest-sent-ledger faulttest-count
```

```powershell
gcloud pubsub topics delete faulttest-decisions
```

```powershell
Remove-Item -Recurse -Force orchestrator/runs/faulttest
```

A failing check is a finding: report it as found rather than re-running until it passes.
